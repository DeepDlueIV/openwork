# NoClip: установка, обновление и скачивание для Windows

## Где скачивать

Workflow настроен публиковать проверенные тестовые установщики в [Releases](https://github.com/DeepDlueIV/openwork/releases) с пометкой **Pre-release** только после успешных проверок. Файл для Windows x64 называется **NoClip-Setup-x64.exe**. На странице опубликованной версии есть прямая ссылка, SHA256SUMS.txt, BUILD-INFO.txt и INSTALL-SMOKE.json. Исходный код и ZIP из Actions для установки не нужны.

Не использовать `/releases/latest` для поиска тестового выпуска: предварительные версии не являются стабильным Latest. ZIP в Actions остаётся дополнительным способом скачивания и хранится семь дней; вложения Release этим сроком не ограничены.

**Не устанавливать старую `noclip-baseline` рядом с OpenWork.** Сборка №4 (`1fa692cdbe9d0e6e6856e02d09d62acc0e5f61ed`) ещё использовала общую идентичность и профиль OpenWork. Новая сборка использует `electron-builder.noclip.yml`: `NoClip`, `io.github.deepdlueiv.noclip`, `noclip://`.

## Как обновлять опубликованную сборку

1. Завершить текущие задачи и закрыть NoClip.
2. Скачать новый `NoClip-Setup-x64.exe` со страницы версии.
3. Запустить его поверх существующей установки. Предварительно удалять программу не нужно.

Идентификатор приложения и имя пакета должны оставаться постоянными между версиями: по ним установщик находит существующую программу. Обновление заменяет программные файлы, а не создаёт отдельную установленную программу для каждого номера версии.

Встроенное автообновление и восстановление из выпусков OpenWork отключены. Собственного автоматического обновления NoClip пока нет; новая версия устанавливается вручную указанным способом.

## Где данные и что происходит при удалении

Профиль NoClip находится в `.noclip` внутри настоящей домашней папки пользователя ОС, обычно `%USERPROFILE%\.noclip` в Windows. Интерфейс хранит своё состояние в `.noclip/desktop`; настройки, базы движка, сохранённые учётные данные и кеши — в `.noclip/runtime`. Старый профиль OpenWork автоматически не импортируется.

Обычное удаление NoClip намеренно сохраняет профиль, включая чаты, настройки и сохранённые ключи/токены. Повторная установка использует тот же путь. Это пользовательские данные, а не незавершённое удаление программных файлов. Файлы в выбранных пользователем рабочих папках не должны удаляться установщиком или деинсталлятором.

Для полного удаления данных нужно отдельно закрыть NoClip, удалить программу и затем явно удалить только папку `.noclip` своего пользователя. Это уничтожит историю, настройки и сохранённые учётные данные. Перед очисткой следует сохранить необходимые данные. Папки OpenWork и рабочие проекты удалять не нужно. Отдельная кнопка полной очистки этим изменением не добавлялась.

## Что проверяет CI

- Девять проверок идентичности, путей и блокировки upstream-updater на Windows/macOS/Linux.
- Проверки ожидания удаления: задержанная очистка реестра, задержанное удаление EXE, оба варианта постоянного остатка и уже завершённое удаление.
- 23 проверки desktop session-runner/journal на Windows и проверка метаданных готового `app.asar`.
- Два настоящих установщика из одного исходного коммита: младший номер версии `0.18.58-noclip.0.0` и текущий номер.
- Установка младшей версии, замена новой без ручного удаления, сохранение того же пути и записи приложения, обычное удаление, повторная установка и повторное удаление.
- Неизменность SHA256 четырёх контрольных файлов профиля NoClip и пяти контрольных файлов оригинального OpenWork после каждого этапа.

NSIS запускает временную копию деинсталлятора, а файлы удаляет раньше записей реестра. Поэтому завершение первого процесса или исчезновение одного EXE не является критерием завершения. Проверка ждёт одновременно исчезновения EXE и точной записи реестра с ограничением времени. Она не чистит реестр вручную и не скрывает постоянную ошибку удаления.

При проверках обнаружена также временная Windows-блокировка атомарной замены журнала (`EPERM`), переживавшая прежние 380 мс повторов. Повторы ограничены 1,58 с ожидания; старый журнал не удаляется и не обнуляется. Постоянная ошибка по-прежнему останавливает обработку. Проверки включают контролируемую длительную блокировку и настоящий Windows-дескриптор читателя.

Младший установщик использует тот же код, а файлы профиля в тесте — контрольные образцы. Это проверка механизма установки и сохранности файлов, **не проверка миграции реальных баз между изменившимися версиями приложения**. Перед будущими изменениями формата данных нужна отдельная миграция с резервной копией и проверкой перехода с предыдущего реального выпуска.

Сборочное задание имеет `contents: read`. Отдельное задание публикации получает `contents: write`, не запускает код приложения и повторно проверяет checksum, исходный коммит и результат install-smoke. Оно сначала загружает вложения в черновик, затем публикует Pre-release; при провале сборки публикация не выполняется.
