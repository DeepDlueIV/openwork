# NoClip: отдельная тестовая сборка Windows

## Основа и рабочие ветки

- Репозиторий: `DeepDlueIV/openwork`, основная рабочая ветка: `noclip`.
- Изоляция разрабатывается и проверяется в `noclip-install-isolation` перед переносом в `noclip`.
- Основа: OpenWork `v0.18.58`, коммит `258218b9b69c91e3d5020488fe1d14ff767679e9`.

Ветка создана от релиза, а не от вершины `dev`. Число отсутствующих коммитов при сравнении с upstream `dev` не зависит от даты создания форка. Не переносить всю `dev` ради устранения этого индикатора.

## Что отделено

Сборка использует `apps/desktop/electron-builder.noclip.yml`: имя `NoClip`, идентификатор `io.github.deepdlueiv.noclip`, протокол `noclip://`, собственные установщик, запись удаления и ярлык. Исходные конфигурации сборки OpenWork сохранены.

Профиль располагается в `.noclip` внутри настоящей домашней папки учётной записи ОС. Electron хранит данные в `.noclip/desktop`; конфигурация, базы движка, учётные данные и кеши — в `.noclip/runtime`. Изоляция устанавливается до загрузки модулей OpenWork. Старые чаты, настройки, SSH-ключи и пользовательские shell-профили автоматически не импортируются. Выбранные пользователем проекты доступны; это разделение приложений, не системная песочница.

Обновления и загрузка версий для восстановления отключены на основании метаданных самого пакета. Переменная окружения или выбор канала не включают updater OpenWork. Собственного сервиса обновления NoClip пока нет.

Удаление NoClip сохраняет его профиль и не выполняет исходный скрипт очистки ярлыков OpenWork. Подробности: `docs/noclip/installation-isolation.md`.

## Проверки и упаковка

Workflow `NoClip installation isolation` выполняет девять проверок на Windows, macOS и Linux. Для коммита `1a0896214223e19066bc5fdb725d971c01ab4ee3` все три задания прошли: https://github.com/DeepDlueIV/openwork/actions/runs/39594314098 .

Workflow `NoClip Windows test build` использует Windows Server 2022 x64, Node.js 24, pnpm 11.4.0, Bun 1.3.10 и `--frozen-lockfile`. После проверки изоляции он собирает приложение, запускает 21 проверку session-runner/journal, упаковывает NoClip, проверяет метаданные и блокировку updater внутри готового `app.asar`, затем устанавливает и удаляет приложение на одноразовой машине с контрольными файлами оригинального OpenWork.

Установщик публикуется в artifact только после успешного завершения всех этих шагов. Workflow имеет `contents: read`, не использует пользовательские секреты и не создаёт GitHub Releases.

Для текущего кода запущена полная проверка Windows № 6: https://github.com/DeepDlueIV/openwork/actions/runs/39594314227 . На момент этой записи её итог ещё не подтверждён. Успех модульных тестов не означает успех упаковки или установки.

## Как отличить новый установщик

Новые артефакты: `noclip-isolated-windows-x64-<номер>-<попытка>`.
Внутри: `noclip-win-x64-<версия>.exe`, `SHA256SUMS.txt`, `BUILD-INFO.txt`, `INSTALL-SMOKE.json`. Хранятся семь дней. Точный исходный коммит указан в `BUILD-INFO.txt`.

**Старая сборка № 4 — не изолированная.** Artifact `noclip-windows-x64-4-1`, установщик `noclip-baseline-win-x64-0.18.58-noclip.4.1.exe`, коммит `1fa692cdbe9d0e6e6856e02d09d62acc0e5f61ed`. Она сохраняет идентичность, профиль и updater OpenWork: не использовать её для установки рядом с личным OpenWork.

## Границы результата

Это неподписанный тестовый установщик, а не публичный выпуск. Проверка установки/удаления не заменяет запуск и проверку графического интерфейса. Интеграция Shluz, полный ребрендинг, совместная работа двух реально запущенных приложений, установщики macOS/Linux и Windows ARM64 здесь не подтверждены. Наличие оригинальных иконок и отдельных названий в интерфейсе ожидаемо. Работающие внешние функции OpenWork не удалены этим этапом.
