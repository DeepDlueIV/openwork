# NoClip: контрольная сборка Windows

## Исходная точка

- Репозиторий: `DeepDlueIV/openwork`, рабочая ветка `noclip`.
- Основа: OpenWork `v0.18.58`, коммит `258218b9b69c91e3d5020488fe1d14ff767679e9`.
- Сценарий: `.github/workflows/noclip-windows-test.yml` — **NoClip Windows test build**.
- Цель этого этапа: собрать исходное приложение из нашего форка. Интеграция Shluz, ребрендинг, отдельные профили и собственный updater пока не реализованы.

## Что делает Actions

При изменениях перечисленных в workflow файлов в ветке `noclip` запускается одна сборка на стандартном `windows-2022` runner для x64. Используются Node.js 24, pnpm 11.4.0, Bun 1.3.10 и существующий lockfile (`--frozen-lockfile`). Версии движков берутся штатным сборщиком из `constants.json`.

Штатный `build:electron` собирает интерфейс, сервер и локальные компоненты. Затем выполняются `test:session-runner` и упаковка NSIS с `--publish never`. Версия пакета имеет вид `0.18.58-noclip.<номер запуска>.<попытка>`; файлы исходного приложения этим не меняются.

В artifact `noclip-windows-x64-<номер>-<попытка>` сохраняются установщик `.exe`, `SHA256SUMS.txt` и `BUILD-INFO.txt` с точным исходным коммитом. Срок хранения — 7 дней. Отсутствующий или подозрительно маленький установщик завершает job ошибкой. Новая сборка той же ветки отменяет предыдущую незавершённую.

Workflow имеет только `contents: read`, не использует пользовательские секреты и не публикует GitHub Releases. Телеметрический DSN Sentry при сборке не задаётся. Это не утверждение об отсутствии всех сетевых обращений исходного приложения.

## Как получить установщик

Открыть **Actions → NoClip Windows test build → успешный запуск → Artifacts**. Скачать ZIP, распаковать и прочитать `BUILD-INFO.txt`. При необходимости сравнить SHA256 установщика командой PowerShell `Get-FileHash -Algorithm SHA256 <путь к exe>`.

В новом форке Actions могут быть отключены. Если GitHub показывает кнопку **I understand my workflows, go ahead and enable them**, включить Actions. Уже пропущенное событие push при этом не воспроизводится: нужен новый подходящий коммит. Существующий запуск можно повторить через **Re-run all jobs**.

`workflow_dispatch` предусмотрен, но кнопка **Run workflow** обычно появляется только при наличии этого workflow в default branch. Пока default branch — `dev`, основной способ запуска — push в `noclip`. Не переносить все изменения `dev` в `noclip` ради этой кнопки и не запускать исходные release-workflows авторов.

## Ограничения и безопасность проверки

**Это неподписанная контрольная сборка OpenWork, не готовый NoClip.** Имя и идентификатор приложения, рабочие данные и источник обновлений остаются исходными. Установка может затронуть личный OpenWork, а встроенный updater — предложить официальный выпуск вместо нашей сборки. Проверять установку и запуск только в одноразовой Windows VM; не устанавливать поверх личной версии и не пользоваться встроенным обновлением. Отдельная безопасная установка рядом с OpenWork — следующий самостоятельный этап.

Успешный Actions подтверждает только выполненные шаги сборки, тестов и упаковки. Он не доказывает запуск GUI, установку/удаление, работу через Shluz или поддержку macOS/Linux/Windows ARM64. Предупреждения Windows о неподписанном издателе не требуют отключения защит ОС; публичное распространение требует отдельного решения о подписи.

Статус первого фактического запуска нужно проверять в Actions, а не выводить из наличия этого файла.
